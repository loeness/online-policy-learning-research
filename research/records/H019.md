## 原始问题、主张与机制

原问题是：在一个共享位置中保留旧模块或保存新模块，完整在线学习后果是否会随未来旧/新情境的复现分布变化；过去复现频率能否支持只读过去信息的规则，超过固定 keep / replace。机制是从同一 learner 和模拟器前缀分叉 keep、replace、mean、none，之后继续 PPO、critic 更新及自然 LRU 淘汰。一个固定预训练 W0、两个局部槽和一个共享位置；任务组信息受控提供，故不检验未知情境发现。

## 原始可观测预测与判别规则

协议定义 D = R(replace) − R(keep)，I = D(new-major future) − D(old-major future)。机制方向的探索性支持条件是：每个关系的平均 I 为正、至少 6 / 8 个 seed 的 I 为正，并报告 seed-cluster 区间；每步奖励 0.002 是实际量级参考，不是确认门槛。过去信息规则须在主条件 history = future 中直接优于 keep 和 replace，才能说明超出始终采取单一行动的价值；mean 也作为控制。更精确的普遍选择器阈值：UNKNOWN。

## 轮次配置、比较与预算

- 环境 / 数据：固定 W0 的小型导航任务族；dynamics 与 reward_conflict 两种关系。8 个新部署 seed、每 seed两种关系和两种历史，共 32 个前缀；两种未来比例、四种保存操作，共 256 条未来分支。
- 协议：每个共同前缀从两种旧 / 新在线来源形成候选；单次保存后继续 12,288 步真实环境交互。rollout 为 256 步；未来日程、组关系和边界作为受控实验信息，past-only 规则在未来展开前冻结。主要基线为 keep、replace、mean、none，以及 frequency、gain、lower。
- 主要指标：完整未来累计奖励 / 步；I 和行动偏好反转为机制分析。方向越正越支持“未来复现改变 replace 相对 keep 的价值”；另报前段、分组回报、实际 CPU / wall、包字节与编码漂移。
- 完整持久包上限 262,144 B，actor 容器 89 B；它们是设计上限，不是可重新分配总预算的最优证明。协议预期主交互 3,538,944 步、pilot 27,648 步；结果报告主 cohort 与 pilot 共 3,566,592 步。原批准 compute 上限及剩余额度：UNKNOWN，不据历史用量授权续跑。

## 当前边界与下一决策

当前证据支持“保存行动后果在此任务族中会随未来复现结构改变”，但不支持可靠的自适应保存器、未知情境发现、一般 C2 或普遍算法增益。候选来源的拟合剂量及候选构造仍是混杂因素；后续 H020 / H021 分别检验候选剂量和保存 × 未来 PPO 交互。下一决策是按这些既有证据评估内容与来源暴露，不重复本矩阵；新实验尚未由本记录授权。精确历史 GPU / CPU 时间若不在 run 账本中为 UNKNOWN，不与新机器结果合并。

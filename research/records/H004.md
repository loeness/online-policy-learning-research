# H004：残差表示压缩、修复与替代表示

- **状态：INCONCLUSIVE（Top-K 直接筛选未通过；修复和其他表示仅有探索性证据）。**
- **日期与来源：**`ab_plus_protocol.md`（2026-10-13）、`compression_alternatives_protocol.md`（2026-10-14）；提出者未记录。2026-10-20 回顾导入。
- **研究问题与原假设：**已学 residual 能否降低可恢复持久状态成本，同时维持既有行为并继续在线更新？Top-K 协议预设五种保留比例、实际索引/Adam/工作区计量和独立修复流；标准是相对 compact dense 的状态节省与按 context 的性能容忍度。
- **机制与相关文献：**稀疏坐标和值、固定 support online repair；后续比较 exact action-contrast、centered/activation-weighted Top-K、column subset、rank-2 SVD/distillation、BF16。协议明确将 LoRA、Wanda、知识蒸馏列为灵感；对应实验不是这些方法的完整复现。A/B 控制见 [H003](H003.md)，C1 source-basis 表示见 [H006](H006.md)。
- **配置：**来自 B+ terminal checkpoints（41/53/67），原有五个 navigation contexts。主要指标为 adaptive state 和完整 bundle bytes、成功率/回报损失、repair 后表现和训练/推理开销。原阈值见协议；总计算预算未记录。

## 结论边界与下一判断

**事实：**直接 Top-K 筛选失败；额外经验能修复其中固定 50% 的平均性能代价；其他表示在有限 seeds/contexts 上结果混合。**解释：**压缩的效用需按真实持久状态、优化器、工作区和恢复成本计算，而不能只看 ZIP 或参数数目。**未决：**三个 checkpoint 来自相同 W0，repair 最低成本未知，计时每方法仅有限样本。下一决定是保留所有失败与修复结果，将候选表示视为条件化组件；不自动授权更广压缩搜索。

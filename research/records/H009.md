# H009 — V2 路由、局部更新保留与整合门控诊断

**状态：** INCONCLUSIVE
**回顾性说明：** 2026-10-20 导入；实现修复和路由诊断发现了瓶颈，但共享整合的独有价值仍弱。
**原始日期与来源：** 2026-10-15；用户要求详细归因并定向优化 V1。原始结构、假设、预测、对照及预算见 [KNOWLEDGE_V2_VALIDATION.md](../../docs/KNOWLEDGE_V2_VALIDATION.md)。当前 H009 是后来导入记录，不是执行前预注册；保存的协议与来源快照仍可证明哪些设计在运行前已冻结。

## 原始问题、假设与机制

V1 累计表现差可能来自四个可分的机制问题：

1. **新槽分配造成局部更新被误回滚。** 预测只清新分配的槽、保留其他槽 trial 更新会改善在线学习；修 bug 不是论文创新。
2. **路由证据不对称导致原型碎片化。** 近期有界一致后缀、共同支持单元兼容性、未知单元不算冲突、暂存与持久库分离，应在保持覆盖时减少重复分裂。
3. **局部学习与共享接受绑在一起。** 先以独立 int8 保护局部 PPO 更新，再只在共享编码更省字节且 KL 失真受限时替换，应降低整合失败对局部学习的伤害。
4. **经验 gate 分数不一定代表真实策略改进。** V1 的 candidate/incumbent 评分使用 trial 策略采样数据；改用真实 behavior 概率作为诊断分母会改变分数，但不被假设为安全保证。

**借鉴来源：** Progress & Compress 的局部学习/慢整合、DaCoRL 的动力学证据路由，以及 TRPO 对采样参考分布的区分。实际代码不是这些方法的完整复现，也未继承其保证。

## 配置与边界

- **环境/数据：** 同一 C1 导航 W0、隐藏切换安排和真实奖励，动作前历史统计路由；正式 V2 使用 seed 541/557/569。oracle 条件使用 privileged hidden schedule，只作因果诊断。
- **因果对照：** 6 条件 × 3 seed × 32,768 步，比较旧路由/旧分配、只修复分配、oracle int8、旧路由 dense、oracle dense、oracle 旧 gate；int8 320 B 上限，dense 664 B。PPO 每 1,024 步 3 个训练 rollout + 1 个 holdout。
- **V2 闭环对照：** 单头、修复后的旧路由 int8、新 EvidenceRouter int8、新路由旧 gate、新路由非阻塞整合；每臂每 seed 32,768 步，W0 文件加 checkpoint 有 256 KiB 的持久化边界检查。
- **其他比较：** 同一已保存行为流的 EvidenceRouter 离线回放；seed 787、8,192 步的 gate 评分诊断；15 个终点、逐情境逐 episode 配对重访。
- **主指标：** 固定真实交互步数的在线奖励/步，成功率、路由覆盖/ARI/纯度/分配和驱逐、actor 字节与完整恢复包、重访保留—清除的配对差和实耗。奖励、覆盖、持久性越高越好；开销/容量越低越好。
- **历史成本：** 因果正式 589,824；V2 正式 491,520；因果/V2 两个 pilot 合计 73,728；score diagnostic 8,192；V2 revisit 80,319；router replay 0 环境交互。总计 1,243,583。当前没有追加实验的 compute 或 storage 授权。
- **保护边界：** 原正式数据、失败和报告不覆盖；本次仅新建分配的 H/E 与 provenance 文件。历史执行修改范围未完全记录时标为未知。

## 观测事实

**因果归因。** 正式奖励/步为：旧路由 int8 −.016267；仅修复 trial rollback 后 −.014477（改善集中于一个 seed）；oracle int8 −.004182（三个 seed 均好于修复后的旧路由）；旧路由 dense −.016333，没有超过 int8；oracle dense −.006097；oracle route + 旧 gate −.011049，低于 oracle int8。oracle 结果是 privileged diagnostic，不是未知情境算法成绩。该结果支持把路由和 gate 分开处理，不表示 oracle 可部署。

**路由保存流回放。** 正式三流无新增环境交互：新 router 相对原支持度库的覆盖为 93.6% vs 87.5%，ARI 约 .901 vs .650，generation 纯度约 99.4% vs 93.2%，复现复用约 93.1% vs 61.7%，每流分配/驱逐 6/0 vs 27/21。短段 pilot 的 ARI 却从 .442 降到 .397；高覆盖/纯度不能单独证明一般辨识可靠。

**V2 在线与持久性。** 五臂三 seed 正式闭环：单头奖励/步 −.005001、成功率 23.36%，为本轮神经方法平均最优；新路由独立 int8 为 −.012829 / 17.54%；新路由非阻塞整合为 −.010876 / 19.69%，相对独立 int8 只有两个 seed 的收益为正。96 次整合提交中仅 4 次选择 148 B SVD，其余为 202 B int8；全恢复包没有节省。15 终点重访共 1,440 episode / 80,319 步，无梯度：新路由非阻塞整合保持成功率 31.94%、清除后 13.89%、配对回报 +.985；新路由独立 int8 也达到 30.56%、+ .888。共享方法的小增量无法归因于共享编码本身。

**评分诊断。** seed 787、8,192 步；同时记旧分数与以实际 behavior 概率为分母的分数，但始终返回旧分数，动作和奖励与旧 gate pilot 完全一致。10 次候选/回退 probe 中 4 次分数符号不同。这只证明经验判断不同，不是任一分数的安全保证或改良 gate 效果。

## 解释、状态与下一决策

现有证据识别出实现回滚、路由分裂与门控问题，并显示更好的有限路由诊断可减少分裂；然而单头仍有更高的正式在线平均回报，新路由独立 int8 已取得几乎全部终点重访收益，非阻塞共享编码的额外容量与回报收益很小。完整 256 KiB 检查是持久化时边界，不是所有运行时内存上界；六个真情境刚好装入六槽，未验证超容量持续学习。

**状态结论：** INCONCLUSIVE；必要实现修复和情境管理基础得到局部探索证据，自动共享/持久组织的核心主张未被支持。报告提出的下一决策是以同路由、同完整状态预算隔离局部写入、固定共享、在线共享和失败回退，并加入超过容量的重访条件；该建议没有在此导入中注册为新 H，也没有获得新的实验授权。若后续决定执行，需先按研究日志分配新编号和预算。

- 提出者：UNKNOWN；原始 H 独立登记日期、初始 PROPOSED 状态及逐次状态历史：UNKNOWN。不得把本次回溯摘要称为预注册。
- 原始证据来源：[冻结协议](../../docs/RETENTION_MECHANISM_PROTOCOL.md) 与 [结果审查](../../docs/RETENTION_MECHANISM_REVIEW.md)。

## 原始问题、主张与机制

本轮有两个相连但区分的疑问：既有 selected-feedback MSE 改善是否主要来自 CPU 成本噪声；以及匹配候选来源拟合量后，keep / replace / mean / none 的完整在线后果能否在更长时域或独立随机续程中显出可重复差异？阶段 0 是既有日志的只读分解；阶段 1 固定 W0、同前缀来源和候选，付费展开四行动分支并嵌套观察 1,536 / 6,144 / 12,288 步。观察者 best-action 不等于部署 selector。

## 原始可观测预测与判别规则

阶段 0 分别比较 reward、CPU、原效用的 prequential MSE，并分解误差及协方差；不存在独立 RL 成功门槛。阶段 1 的主要指标为奖励 / 步，重点报告 replace−keep、未来比例交互及跨随机续程选择−keep / 固定 replace；+0.002 是实际量级参考。原协议未设一个正增量的普遍 acceptance threshold：UNKNOWN。跨续程选择使用一条未来选择、另一条评分，是 observer 诊断，不作部署效果预测。

## 轮次配置、比较与预算

- 环境 / 数据：既有 H023 六 seed、两关系、64 决策 / 流的校准数据作 Stage 0（零新增环境交互）；Stage 1 用固定 W0、dynamics / reward_conflict、六个新 seed、两种历史，共 24 个前缀。
- Stage 1 protocol：每个 seed×关系×历史有 7,168-step prefix；来源在保存时各拟合 1,024 步；四种操作 × 两未来 × 两随机 replica，共 384 条分支，每条 12,288 步。保留来源、RNG transformation、前缀和分支 checkpoint；嵌套窗口不算独立样本。
- 比较指标：主 horizon 12,288 的 reward / step 越高越好；CPU / reward-minus-CPU utility、安装成本、源曝光、编码漂移、容量另报。fixed-action 对照是 keep / replace / mean / none；observer 诊断不训练 selector。
- 配置包沿用 actor 89 B、complete-package cap 262,144 B。计划主 4,890,624 步、pilot 56,320 步；实际正式 4,890,624 步，另含失败首次 pilot 7,168 步及 pilot v2 56,320 步，共 4,954,112 步。Stage 0 与报告 / 审计新增环境步 0。历史授权上限 / 剩余额度：UNKNOWN。

## 当前边界与下一决策

证据不支持“只延长结果窗口即可得到可靠保存选择增量”。在匹配来源拟合时间的这个候选下，部分行动后果仍与未来复现比例相关，但 observer 看到了条件未来，不能部署。下一项应处理候选内容和晚期状态覆盖，关联 H026；不据此增加 selector 复杂度。source equality 是拟合时点的步数匹配，不是等质量结论。

# E164 算法侧机制分析与本轮结案

日期：2026-10-23（Asia/Singapore）。本分析属于同一E164的算法侧结案，只读既有JSON与报告，没有导入科学模块、重新拟合/评分、测试或远端操作。

**算法结论：在保持转后新训练KL复查时，仅放开closure接纳没有改变最终交付；绕过复查释放了旧行为保护，也释放了新行为拟合代价，尚不支持把UG或UR升级为保存算法。** [H036](../../records/H036.md)保持INCONCLUSIVE，E163固定v1的8/16及停止决定不变。

证据依据：[最终交付](../../../experiments/exp164/FINAL_VALIDATION.json)、[统计报告](../../../experiments/exp164/analyses/a001/report.md)、[逐项摘要](../../../experiments/exp164/analyses/a001/analysis_summary.json)、[最终独立审计](../../../experiments/exp164/analyses/a003/audit.json)及[主控集成分析](COORDINATOR_E164_SYNTHESIS_20261023.md)。有效性为COMPLETE_VALID / EXPLORATORY_ONLY；最终审计含已披露的离线字段映射修正，原失败审计和修正链保留，不能表述为原冻结核验器一次通过。

## 1. UG−V为何全16项精确为零

三标签共用原lambda=1训练目标、初始化和搜索路径：V选择受新训练KL界约束的F64，再做转后复查；UG选择全部已访问有限点中完整目标最低的U64，但保留同一转后复查；UR使用同一U64，诊断性绕过该复查。closure接纳仅更新返回incumbent，不改变L-BFGS收到的目标和梯度。

零差值有两种明确来源，不能合称16次新测量都没有信号：

- **11个复用项**：F64/U64科学哈希相同，原float32回退未触发，三个标签准确引用同一原D候选及评分。这11行的零由身份相同决定。
- **5个恢复项**（26204/26206/26209/26212/26213）：F64/U64哈希不同，恢复轨迹精确匹配原记录；UG的U64转后新训练KL复查全部失败，回退到C0的最终字节，恰与V相同。UG因此按字节别名复用V评分；UR保留不同的U候选，另行评分。

实际完成5次恢复、5个真实V锚点和5个UR评分，共10个新完整评分包；所有候选先锁定，全部V锚点通过后才评价后续探针。UG−V在编码前/后、训练/留出均精确为零，是候选身份与回退路径的结果，不是“统计功效不足未检出差异”。其含义仅限于**保留这道后续复查时**放开closure接纳没有交付增量，不能推广为任何后续规则下closure接纳都无作用。

## 2. 转后复查拦住了什么

原训练完整目标为新KL＋旧KL＋单次ridge。降低该标量允许旧项收益补偿新项损失，并不要求两个KL同时下降。输出复查另要求新训练KL不差于C0加1e-12；它是交付约束，不是搜索目标中的等价条件。

以下只抄录五项原始记录，数值为新训练KL：

| 26206 | 0.090254619 | 0.098497199 | 0.098497239 |
| 26209 | 0.129212503 | 0.151659903 | 0.151659928 |
| 26212 | 0.092576786 | 0.123619917 | 0.123619889 |

来源为[原始cases](../../../experiments/exp164/runs/run001/remote/cases/)中对应seed的`trace.json: diagnostics.u_best_float64_new_train_kl`及`lock.json: probes.UG.baseline_new_train_kl/raw_cast_new_train_kl`；完整精度和回退/别名见逐项摘要。

**五个U64在转型前就已越界，U32仍越界。** UG不是把一个已满足原界的float64点单纯因舍入误差淘汰。UR−UG比较的是同一U候选被接纳还是被换回C0，识别转后新训练KL约束的作用；两者并未采用不同的float32精度。随后完整actor的int8编码是另一环节，不能与这道float32复查混为一谈。锁没有独立命名的fallback_reason字段，本分析依据记录的复查结果、fallback布尔值和最终字节别名，不补造其他返回原因。

## 3. UR−UG的保护收益与新行为代价

下表均按预定**全16项**计算，旧KL越低越好，`G_new=K_new,W0−K_new`越高越好；变化来自5项恢复，其余11项为准确复用零行。

| 指标与阶段 | 全16平均变化 | 改善／退化／不变 |
| --- | ---: | ---: |
| 旧KL，编码前训练 | −0.180596147892 | 5／0／11 |
| 旧KL，编码后留出 | −0.221881294348 | 5／0／11 |
| G_new，编码前训练 | −0.011567447967 | 0／5／11 |
| G_new，编码后训练 | −0.014298905227 | 0／5／11 |
| G_new，编码前留出 | −0.012279031886 | 2／3／11 |
| G_new，编码后留出 | −0.016072061517 | 2／3／11 |

这支持H036的一个有限机制预测：在同一九系数父、相同绑定与编码预算内，搜索确实产生了相对V更贴近旧teacher、且这种旧保护能保留到编码后留出的候选。保护对象仍是**当前已解码旧父、local=0的keep初始化prior**，不是已淘汰来源的完整策略或所有旧任务知识。

它同时削弱“释放这些点即可得到无代价兼容改进”的解释。新训练收益在五项全部下降；新留出收益在26204/26206/26209下降，仅26212/26213上升。训练目标的标量改善没有保证新旧各项共同改善，训练接纳界也不等同于留出共同收益边界。复查在本批次确实限制了旧保护点的交付，同时承担了阻止这些新训练拟合退步的作用，不能只把它视作妨碍优化的障碍。

新留出两项上升而新训练五项全下降，说明训练代价与当前留出代价并非逐项同号；这不证明训练约束普遍错误，也不证明已找到可用的留出收益预测规则。平均新收益在编码前已下降，故不利权衡不能全部归结为最后的codec；编码前后幅度不同，仍不排除编码的影响。

## 4. 两个局部共同改善点与结论边界

26212、26213相对UG的编码后旧/新留出变化分别为：旧KL−0.853253018079、G_new＋0.032450905769；旧KL−0.793927182997、G_new＋0.128718827044。它们是当前固定容量、既定teacher与有限留出上的局部共同改善样例；不是通过原E163联合门槛的同义词，更不能事后仅保留这两项形成选择器或宣称成功率。

候选选择在评分前按训练规则锁定，恢复集合按缺失候选身份确定，全部16项都保留。现有结果可解释这两个样例，但没有提供操作前识别它们的规则。11个复用零行也不能当作11次独立重复验证，或据此外推未来发生频率。

本轮只评价预定F/U选点：没有穷尽同一轨迹的其他候选，没有全局优化证书，没有检验所有函数或优化器。因此失败和取舍不证明整个函数类无兼容解；两个共同改善样例也不证明普遍兼容。数据复用已见E161/E163状态及留出，不是新种子独立确认。没有新增环境交互或后续reward分支，KL变化不建立在线恢复、保存动作净价值、未来任务频率下效用或reward收益。

## 5. 本轮算法结论与停止

**E164回答了预定有限问题：仅解除closure接纳在原转后复查下无交付变化；解除转后复查则产生可定位的旧保护／新拟合取舍，尚无统一改善。** 它补足机制解释，不把H036变成已证实算法贡献，不直接删除复查或把UG/UR部署为新规则。H036仍INCONCLUSIVE，E163固定v1停止决定保持。

本轮验证、主控解释与本算法侧分析均已完成。唯一reservation关闭且余额退役，作业/SSH已结束；不是因预算耗尽才停止。campaign观测CPU约7.929755秒、footer前墙钟约9.350687秒；含收尾预留的保守上界约12.929755／19.350687秒，不冒充精确完整实耗，未测成本保持UNKNOWN。证据、失败和离线审计修正链全部保留。本轮到此结束，不自动补候选、换lambda、扩结构、分配新E或进入下一次验证。

待用户决定的下一问题仅保留为：**在现有固定容量与teacher下，允许怎样的新行为代价，才可能与留出上的旧新共同收益相容？** 本文不据此提出新方法、合同、实施步骤或预算。

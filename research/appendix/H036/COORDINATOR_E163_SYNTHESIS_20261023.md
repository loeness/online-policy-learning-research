# E163 主控结论与下一问题

集成日期：2026-10-23（Asia/Singapore）。这是已完成 E163 的结果后分析，复用最终标量诊断与独立审计；没有重新拟合、环境交互、模型反序列化或远端执行。原始假说、规格、门槛、失败记录和冻结版本不改写。

**决定：接受 E163 run002 为 COMPLETE_VALID / NO_ADVANCEMENT；H036 为 INCONCLUSIVE，停止固定 v1。** 16 个固定 prefix、32 次拟合全部有效，联合门槛 8/16，低于预设 12/16。完整[实验报告](../../../experiments/exp163/analyses/a002/report.md)、[逐 prefix](../../../experiments/exp163/analyses/a002/per_prefix.csv)、[逐 fit](../../../experiments/exp163/analyses/a002/per_fit.csv)、[独立审计](../../../experiments/exp163/analyses/a002/audit.json)与[主控接受记录](../../../experiments/exp163/preparation/coordinator_result002_acceptance.json)构成证据链。

## 科学问题与本轮支持范围

C/D 都采用相同 wildcard 绑定、同一个九系数父模块、相同输入/初始化/优化上限及原始完整 actor codec；受控差异是旧行为项 lambda=0/1。旧教师是 keep 后 local=0 可继承的旧父初始化 prior，而非已淘汰来源的完整策略。最终评分是实际完整编码后 fresh local=0 的留出 KL。

本轮显示：这个固定实现可以在部分 prefix 上同时保护旧 prior 并保留新来源拟合收益，但不能在预设覆盖范围内稳定达到要求。7 个通过项 D 返回非 C0；另一个通过项 26209 返回初始 C0，仍合法计入8/16，但不能把它的通过归因于学到的保护更新。

这是有边界的机制证据。它不建立未来 reward 增益、优于 keep 的在线收益、完整知识组织算法的贡献或未知情境能力，也不证明整个函数类无法兼容。通用旧行为 KL 本身的文献借用范围保持不变，本轮没有建立其新颖性。

## 失败不是同一种问题

以下按互斥顺序组织全部8个失败项，仅用于结果解释；正式分母始终为16，不按事后子集重判门槛。

| 失败位置 | Prefix | 含义 |
| --- | --- | --- |
| 无保护 C 在最终留出上没有优于 W0 的新收益 | 26206、26208、26218 | 不能一概归因于旧保护项牺牲新知识；新候选的基础收益已经不成立。26218 的 D 有正新收益，但不能据此删掉原 guard 或改写筛查。 |
| C 有正新收益，但 D 的旧 KL 未降低至少25% | 26204、26212 | 两者 D 均返回 C0；本固定搜索/接纳/编码流程没有交付足够旧保护。 |
| C 有正新收益，D 旧保护达标，但新收益保留不足50% | 26210、26213、26216 | 在这些 prefix 上出现了不满足预设要求的旧/新折中；其中26213的D返回C0。 |

原始条件计数有重叠：C无正收益3个、旧保护不足2个、新收益保留不足5个。不能相加成10个独立失败。旧保护比例条件本身14/16达到，说明只看平均旧KL或该单项会掩盖联合失败。

全16个prefix的描述性均值如下，不作为额外成功指标，也不替代联合门槛：

| 最终编码后指标 | C | D | D−C |
| --- | ---: | ---: | ---: |
| 旧holdout KL | 1.17558 | 0.26965 | −0.90593 |
| 新holdout相对W0的收益G_new | 0.12650 | 0.08781 | −0.03869 |

D 共5次返回C0（26204/26206/26209/26212/26213）；32次 termination 都是 optimizer_completed，没有 float32 fallback。正常结束不等于达到最优或满足机制门槛；C0也不等于程序错误。

这5个C0日志各有67–75条closure，其中66–74条标记被new_train_kl_gate拒绝，另有一条未标拒因；最终新训练KL与初始相等，best Float64完整目标也与初始相等。因此“完整双目标搜索产生的点，被以C0新训练KL为限的接纳规则大量拒绝”是已观察到的执行路径。日志没有显式C0返回的唯一原因，不能推断去掉过滤就会过门槛，或不存在其他可行候选。

## 容量、编码与成本

32个actor均89 B，完整持久包233500–234681 B，小于262144 B；没有以增容解释本次差异。补偿前有效矩阵近似保持，不代表量化后函数保持：实际 resident KL最高0.04870864、概率最大绝对漂移最高0.2184344。编码前后旧/新留出KL的变化也有正有负；这些诊断使编码值得定位，但不足以直接断言它是8/16失败的根因。

进一步只读比较已有编码前诊断：当前8个失败项在编码前已经分别不满足对应条件。C的3个非正新收益在编码前已为−0.09111、−0.02996、−0.00667；两个旧保护失败的编码前C/D旧KL分别为0.08004/0.16900与1.00505/0.96318；其余3个新收益保留失败的编码前D收益为0.00971、−0.05577、−0.09519，也已低于各自C收益的一半。因此对这批已选候选，不能把整体失败归结为最终codec；编码前指标仍不用于重判正式结果。优化充分性、训练到留出迁移和函数类表达能力之间仍不能作因果归因。

run002观测CPU小计8.625535秒、footer前墙钟10.011705487秒；含收尾保留额的上界分别13.625535秒和20.011705487秒，均在120/180上限内。上界不是精确实耗；SSH、回传和本地证据审计属于另记运维。新交互0、GPU0。原始250文件/6875913 B完成字节核验，独立审计1876项、0失败。

run001保持 ACCOUNTING_INVALID，累计完整E163 CPU/墙钟仍UNKNOWN；run002不能修补该缺口。两个单次reservation均关闭，无可复用余额。[唯一预算账本](../../../experiments/exp163/budget.json)的执行开关关闭、active_job为空。

## 下一问题与交付边界

下一问题选为 H036 内的失败定位：**完整双目标搜索与“新训练KL不得差于C0”的接纳规则，是否限制了本轮实际可交付的新旧折中；它与留出失败分别是什么关系？** 编码前已出现当前失败，故不把改codec作为第一项，不先搜索lambda、增加父模块或启动奖励实验。

已有全部16个prefix的训练/留出、编码前后、C0与闭包日志足以完成上述局部定位，下一份设计应复用这些证据，不重复做相同诊断。闭包记录只有标量与哈希，虽保存了一个best Float64候选，未保存整条候选轨迹，不能重构未记录备选的编码留出表现。这是结果后诊断问题的登记，不是新的已支持假说，也不恢复E163的执行授权。

如需下一轮诊断程序，算法实现负责交付允许输入、必要字段、精确比较、禁止泄漏项、最小实现及冻结版本；主控根据该交付决定是否登记新E及预算。消融实验（1）只独立审查并执行已冻结、已授权的诊断，不在运行中解释或修改科学语义。未授权新fit、lambda搜索、StageA、新seed或结构扩展。

算法实现的下一份设计至少要说明：搜索目标、接纳约束和最终编码留出门槛的关系；怎样用最少受控比较区分搜索/过滤限制与训练到留出失配；需要哪些当前未保存的候选信息；固定容量、输入剂量、成本与防holdout选择条件。现有日志无法证明的部分必须转成可证伪预测及具体交付，不能只提出“调lambda”或“多加模块”。这份设计要求尚未构成新实验授权。

## 4. 当前策略与数据：审查时必须匹配

近期策略的概念表达：

```text
z(s) = z_W0(s) + B · [ A_slot,band(s) + I_bound · C ] · ψ(s)
π(a | s) = (1 − ε) softmax(z(s) / T)_a + ε / 4
```

`A` 是每 local 的三个 `3×3` band，共 27 系数；`C` 是广播到三个 band 的 `3×3` parent，共 9 系数；`T` 和 `ε` 均取实际策略配置，四动作均匀混合是现有前向分布的一部分。此处是概念表达，具体轴序、基础特征、温度与探索混合以现有策略接口为准。首轮不改变 W0、local/parent 维度或动作空间。

现有 `BoundedGroupEvidence` 是每组最多 256 条的有界 PPO 行，包括观测、task、bout 和行为概率等。它不保证每个 task 都保有足够观测，也不包含完整的 slot generation 与 parent 版本身份；行为概率来自历史采样时刻，可能跨策略更新混合。

**必须审查的语义：**用历史 victim 观测重算当前教师时，原记录的路由槽位可能是旧分配；需要在副本中按现有接口将 route 设为淘汰时刻的 victim 当前槽，并证明只改路由字段、不改变原始证据。类似地，resident 教师需要其对应当前槽的路由。不得直接把历史 `behavior_probs` 当作淘汰时刻的完整教师，也不得声称有限观测能覆盖整个状态空间。

## 5. 首个待测算法：同组淘汰前行为交接

### 5.1 触发与不可用条件

在合法 rollout/update 边界，当真实发生 victim local 淘汰，且 victim 当前已绑定的 parent 与 victim 属于同一已知组时，才尝试生成写入候选。当前 parent 属于其他组、没有 parent、绑定或版本不确定、必要历史观测缺失、候选非法、容量不足时，**不提交写入**；按原有淘汰流程继续，并记录明确原因。不得以 wildcard 静默覆盖其他组，不新增免费 parent。

当前主控设想首轮只评估限定的单次淘汰决策；不据此推断多次写入的累计稳定性。算法实现需指出如何使只执行一次与真实 runner 时序一致。

### 5.2 教师、数据和拟合目标

在 victim local 清除之前冻结 W0、原 parent `C0`、victim local `A_v`、仍驻留 local、binding、generation 及必要的优化器／缓存状态。利用仅在该时点前已有的观测，以真实策略接口、真实温度和实际 ε 混合重新计算：

```text
victim 教师：π_v^T = π(W0, C0, A_v)
旧 prior：   π_o^T = π(W0, C0, local=0)
驻留教师：   π_r^T = π(W0, C0, A_r)
候选 prior： π_C^0 = π(W0, C,  local=0)
```

旧 prior 仅保护现有 parent 初始化行为，不能说成保护了所有历史旧任务的完整策略。对 t− 前保留的观测，先按预先规定的时间块或样本身份分配拟合与操作验收集，禁止使用未来任务安排、后续奖励、环境反事实或最终测试数据。

主控推荐候选目标：

```text
D_v(C) = mean_{s ∈ S_v,train} KL[π_v^T(.|s) || π_C^0(.|s)]
D_o(C) = mean_{s ∈ S_o,train} KL[π_o^T(.|s) || π_C^0(.|s)]
C* = argmin_C D_v(C) + λ D_o(C) + κ ||C − C0||²_F / 9
```

从 `C0` 初始化；`λ=1`、`κ=1e−4` 是主控提出的待审默认，不是已验证最优值。算法实现需明确每类样本的来源、允许 task/bout 标签的范围、均值和数值精度、时间块与重复观测处理、样本下限、优化器及最大迭代／闭包调用、超限与非有限值处理、实际候选选择及可复现性。若现有证据无法满足合同，请说明需要的最小有界缓存及其代价，不得默认为免费新增状态。

### 5.3 安装、保护与回退

对于仍驻留且绑定原 parent 的槽，对各 band 补偿：

```text
A'_r,b = A_r,b + C0 − C*
```

编码前应保持 `A'_r,b + C* = A_r,b + C0`，未绑定槽不应被改变；该等式允许实现定义的浮点容差，不可直接等同编码后行为相同。

以实际 actor codec 编码、解码候选，包括 parent、所有有关 local 和 binding；在预先固定的操作验收集比较编码后的完整动作概率。提交需同时满足：

1. victim 教师 KL 相对 `C0` no-write 至少改善预注册的 `δ_v`；
2. 旧 prior KL 不超过 `ε_old`，每个驻留槽实际行为偏移不超过 `ε_res`；
3. 版本、组绑定、状态一致性、容量和全部其他冻结不变量成立。

`δ_v`、`ε_old`、`ε_res`、样本数及统计解释目前**未冻结**；算法实现应提出有尺度依据的合同供主控和独立审查确定，不得在查看待验收结果后调节。操作验收不代表独立泛化、回报收益或安全保证。

任一条件失败、证据缺失或执行异常时，不提交候选；恢复写入动作造成的 parent、resident、binding、optimizer、codec 与版本等相关状态，再完成**与原逻辑一致的一次**自然淘汰和新任务分配。需要明确事务边界，使失败不产生重复分配、遗漏分配或改变 RNG/计数；保留足够日志解释实际分支。候选提交后也应明确定义 victim 的清空与新任务绑定顺序、受影响优化器状态以及 checkpoint 的恢复行为。

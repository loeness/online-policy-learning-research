# Compression alternatives: design audit

Read-only audit of the existing compression path and the proposed comparison. No training or environment runs were performed.

## Required gates

1. **Replay calibration logs to recover and validate route history.** The policy input is `[obs, router.summary(), route]` (`src/online_rl/controls.py:481-490`), but `Pkeep_Hclear/steps.csv` records only position/goal, action, next position/goal, reward, route, and confidence (`src/online_rl/controls.py:472-475, 506-515`). The actor uses only the first four coordinates; the eight history values feed the critic (`src/online_rl/policy.py:41-48`). Thus zero history does not change actor-KL or actor activation-norm calculations, but it is not a valid full critic observation. Replay each log from its matching source router snapshot after clearing working memory, using logged pre-action observations, actions, and next observations; recompute `summary()`, `route()`, and confidence, and assert route/confidence match the CSV. `HistoryRouter.observe`, `route`, and `summary` are deterministic from those inputs (`src/online_rl/routing.py:36-55, 116-127`). The existing synthetic probe zero-fills history (`src/online_rl/compression_experiment.py:69-78`); it is valid for actor-only action comparison but not as a complete critic-state probe.

2. **Treat cold restart as part of the estimand.** Existing compression copies source Adam state into packed parameters (`src/online_rl/compression_experiment.py:333-336`; `src/online_rl/compression.py:444-506`), and continuation restores and uses that optimizer (`src/online_rl/compression_experiment.py:227-253`). Existing repair therefore does not measure a cold restart. Fresh Adam, including critic state, is consistent across the proposed arms, but results then describe *cold-restarted post-compression learning*. Compare against a dense-compact arm with the same cold restart; do not attribute its difference from the old warm repair to representation alone. If restart cost itself matters, report the existing retained-versus-reset optimizer diagnostic separately (`src/online_rl/controls.py:757-776`).

3. **Freeze the capacity definition and distinguish empty from warmed Adam.** Existing `packed_0.5` keeps `ceil(0.5 × nonzero_count)` coordinates per residual node (`src/online_rl/compression.py:167-179`). The seed 41 repair reports 260 coordinates total and 3,648 adaptive bytes after updates: 1,040 value bytes + 520 index bytes + 2,088 residual-optimizer bytes (`outputs/compression_attempt/repair/continuation/packed_0.5_s41/summary.json`). This is a 50%-support arm, not 50 coordinates per leaf. The 3,648-byte target is a warmed adaptive-state target; cold Adam initially has no moment tensors. Report weights-only, predicted warmed, and actual warmed bytes for every arm. Keep whole serialized bundle, critic/optimizer/RNG, rollout buffer, compression workspace, and sampled RSS alongside the residual learning-state total. The callback's full training-state metric includes serialized payload plus rollout buffer, while its RSS is a separate process measure (`src/online_rl/compression_experiment.py:200-221`).

4. **Do not label exact action-contrast coordinates as an equal-budget winner.** With two learned residual nodes (`max_nodes=8`, three prototypes in the saved router; `outputs/validated/B_history_keep_s41/router.json`), exact 3 × 65 contrast coordinates use 1,560 residual weight bytes—the same policy-only residual bytes as 50%-support Top-K—but the warmed Adam state raises the adaptive total to 4,688 bytes, above 3,648. Keep it as the lossless diagnostic as planned and state its full warmed size. Other arms need their actual capacity reported; a common cap comparison requires capacity-matched settings or a Pareto comparison.

   Static warmed residual-state estimates from `alternative_compression.py` (assuming every residual parameter receives a nonzero gradient; excludes critic state and optimizer metadata):

   | Arm | Weights/factors + indices | Adam moments + per-parameter steps | Total |
   |---|---:|---:|---:|
   | Dense | 2,080 B | 4,168 B | 6,248 B |
   | TopK50, centered TopK50, activation TopK50 | 1,560 B | 2,088 B | 3,648 B |
   | Exact contrast | 1,560 B | 3,128 B | 4,688 B |
   | SVD2 | 1,088 B | 2,192 B | 3,280 B |
   | Structured 32 | 1,152 B | 2,056 B | 3,208 B |
   | BF16 dense residuals | 1,040 B | 2,088 B | 3,128 B |

   Adam states are lazy. `LeafAdam` leaves an all-zero residual gradient unset (`src/online_rl/policy.py:22-33`), so log actual state after the first update and after repair alongside these predicted warmed values. The installed Adam implementation creates moment tensors with `zeros_like(parameter)` and a float32 step scalar (`.venv/Lib/site-packages/torch/optim/adam.py:167-182`), supporting the BF16 estimate; verify actual serialized dtypes and bytes. The BF16 forward path casts stored values to the FP32 actor activation dtype (`src/online_rl/alternative_compression.py:313-316`), so this is a precision/storage comparison, not a lower-precision compute claim.

5. **Verify the PPO adapter contract for each new core.** The existing adapter exposes `forward`, `evaluate_actions`, `predict_values`, and `get_distribution` (`src/online_rl/compression_experiment.py:27-48`), and the prior dense/packed repair artifacts show that this adapter completed 512 updates (`outputs/compression_attempt/repair/continuation/dense_compact_s41/summary.json`; `.../packed_0.5_s41/summary.json`). That is evidence only for `PackedResidualPolicy`. Each new core must expose those methods with a valid categorical distribution, register every trainable factor/quantized parameter under `core`, and supply the optimizer over exactly those trainable parameters plus the critic. Verify one short checkpoint round-trip and one training rollout per new core before scaling. Keep the base actor frozen as the current continuation asserts (`src/online_rl/compression_experiment.py:255-273`).

6. **Reset Torch RNG after final construction as well as fixing the environment reset.** `StreamEnv.reset` uses `seed * 10000 + 17` on its first reset (`src/online_rl/experiment.py:249-259`), while continuation seeds before constructing the PPO model and swapping in the compact adapter (`src/online_rl/compression_experiment.py:234-249`). Policy/factor construction can consume Torch RNG before PPO samples its first categorical action. Re-seed Python, NumPy, and Torch after each final arm is constructed and immediately before `learn`; retain the explicit common first environment seed. The streams will diverge after policies choose different actions, which matches the independent-trajectory design.

7. **Fail closed on missing calibration for activation-weighted arms.** In `AlternativeResidualPolicy`, a missing/empty activation batch returns unit RMS (`src/online_rl/alternative_compression.py:294-298`), silently turning activation TopK into centered TopK and structured 32 into unweighted column ranking. `_node_calibration_phi` also falls back from the node's route to descendants and then all available routes (`src/online_rl/alternative_compression.py:273-292`). Require nonempty per-node calibration or record an explicit fallback/source-route field; otherwise the claimed arm is not the implemented method. The plan's route replay should assert that no fallback occurred.

8. **Keep the history reset path out of the repair.** `history_reset` can zero a residual and clear its optimizer state on route entry (`src/online_rl/experiment.py:236-240`; `src/online_rl/policy.py:122-128`). The current compression repair passes `history_keep` (`src/online_rl/compression_experiment.py:245`), so it does not trigger that mutation. Keep that method fixed and log/assert it in the new runner.

## Interpretation and leakage controls

- The existing `probability_probe` reports maximum probability difference plus a mean, one-sided reference-to-candidate KL over a synthetic grid; its zero history features do not affect actor probabilities in this architecture (`src/online_rl/compression_experiment.py:69-92`; `src/online_rl/policy.py:41-48`). It is still not a safety bound on visited states. Report categorical KL and maximum probability difference on held-out actor inputs; for approximate arms, add reverse KL or another symmetric summary and worst-state values. Exact contrast should preserve the full action distribution before learning. SB3 `target_kl` is a sampled rollout early-stop rule, not a compression-fidelity or deployment-safety guarantee (`src/online_rl/experiment.py:46-52`).
- The selected `Pkeep_Hclear` logs are prior evaluations (seed formula `400000 + source_seed × 100 + context_index`; `src/online_rl/controls.py:450-455`). Reclassify those observations as calibration and do not reuse their actions, rewards, success, or context label as student inputs/targets. Actions and next observations may be used only to replay router history. Keep new evaluation streams disjoint from calibration and the earlier 900,000/1,100,000 compression screens.
- The current `select_candidate` is hard-coded to `dense_compact` versus names `packed_{fraction}` and summarizes three seeds by means (`src/online_rl/compression_experiment.py:279-309`). Do not use it unchanged for the new arms. Predeclare per-seed paired reporting and per-context outcomes; with three source checkpoints, characterize results as descriptive rather than a strong significance claim.
- Alternative payloads have a separate restore entry point (`src/online_rl/alternative_compression.py:484-489`); the existing `_load` still calls `PackedResidualPolicy.from_payload` directly (`src/online_rl/compression_experiment.py:95-100`). The new runner must route alternative bundles through `restore_payload` or the corresponding class loader.

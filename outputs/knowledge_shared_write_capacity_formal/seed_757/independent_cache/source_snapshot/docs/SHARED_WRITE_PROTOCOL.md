# S1：真实共享写入的顺序验证

2026-10-15。先验证共享参数是否实际改变学习，再引入自动分组、满容量整理和歧义探索。本轮不把给定家族当作自动发现的结果，不改变预训练后持续在线参数学习的研究主题。

## 当前里程碑 S1a

同一个W0、固定27维修正坐标、相同外部情境顺序和真实交互预算；路由由实验器给定。每个种子随机置换槽编号，只有oracle共享条件获得家族分组。四个条件：独立局部修正、局部actor学习率4/3倍的独立控制、持续学习共享父修正、前两个源情境学习后冻结共享父修正。最后一组局部PPO继续训练。

每槽局部修正为3×3×3，每个共享组有一个跨三个区域广播的3×3修正。两个共享组，依赖真实奖励训练。有效修正为 local + shared；在新槽初始化时继承共享参数。该共享形式已有固定结构先例，本轮只隔离持续共享写入相对初期检索的增量。

正式序列A0/B0/A1/B1/A0/B0/A1/B1，各4096步，再分别在A2/B2训练4096步。前两个bout后评估boot，全部seen后评估seen，heldout学习后评估adapted。每次对六情境评估，A2/B2各16个episode，旧四情境各8个。各阶段相同逐episode环境/action随机计划，评估不更新任何参数或全局RNG。A2/B2在seen评估前没有目标策略梯度更新。oracle路由本身有特权，不能称为从零未知情境方法。

主比较为oracle_active对oracle_frozen的A2/B2冷启动回报及其boot→seen变化，同时报告对独立与较快独立更新的结果、旧任务保留、全程在线回报。active/frozen前两个bout必须动作/奖励逐项相同。frozen与independent的heldout行为在boot→seen应完全不变，作为排除评估漂移和目标训练泄漏的检查。

## 学习与资源

复用现有PPO的256步rollout、3个fit+1个holdout、GAE、clipping与entropy；本轮只改变actor分组及每组学习率。critic仍沿用共享的当前观测critic，保持各组一致。没有用旧轨迹回放PPO。float32持久actor编码统一≤1024 B，W0文件+保存checkpoint统一≤256 KiB；该轮关闭量化，不与V2的320 B结果混为同一预算实验。各条件实际分配字节分别记录，较大的共享表示不能宣称压缩节省。Adam不因无损保存而重置，全部条件相同。

首轮开发seed811，缩短为4×2048 seen与2×2048 heldout；正式seed601/619/631/647/659。pilot、正式、评估交互分别计量，负结果保留。CPU单Torch线程，独立运行最多两个进程；当前PyTorch为CPU版。阶段不会修改W0或旧输出。

## 后续门槛与顺序

先看oracle_active相对冻结和独立控制是否有可重复的迁移信号，以及有无严重旧任务损失。该阶段不设事后挑种子的门槛，不把小样本差异称为普遍优势。如果没有增益，先诊断共享写入方式，不直接增加复杂路由。

若有机制信号，再用仅依赖在线经验的兼容性分组替换oracle家族；不足以判断时保持局部。再检验原始情境数超过槽容量的知识保留、压缩和替换，最后检验歧义与探索。后三步另行冻结具体规程；本文件不预先声称已经实现。

保存执行时源码快照、配置、输入hash、原始逐步/逐episode日志、各阶段checkpoint、真实actor二进制字节和完整恢复包字节。检查点用于阶段终点还原，未保存环境/未完成rollout时不声称任意时刻续训。

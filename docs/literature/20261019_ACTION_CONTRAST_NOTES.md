# Shared baselines, action contrasts, and doubly robust feedback

**Status:** literature and design note only. This does not implement or validate a predictor and does not recommend running an experiment before the Stage 1 gate.

## Setting and question

The calibration data has 6 past-only features, 4 storage actions, known uniform logging probability \(p(A_t=a\mid H_t)=0.25\), and 64 decisions per stream. After each selected action, the log contains the observed block reward and CPU use; it contains no outcome for the three unselected actions. The derived target of interest is utility, with CPU rate defined as utility_cpu_s / block_steps and utility as reward rate minus CPU rate.

A shared baseline plus action-relative effects is a reasonable *predictor design to investigate*: it explicitly separates common outcome variation with the logged history from variation associated with the selected action. The original action-specific predictors are observational predictions. Their aggregate prediction errors do not separately report common state or block difficulty versus action-relative error, and differences in model output alone do not establish that this fitted contrast is accurate or causally interpretable.

Identification and prediction are distinct. The known logger assigns each action with probability 0.25 conditional on the full pre-action history, giving positivity and conditional randomization for the current block. Under consistency, no cross-stream interference, and a well-defined block-level potential outcome, the population one-block contrast
\(\Delta_{ab}^{\mathrm{log}}=\mathbb E_{H_t\sim d_{\mathrm{log}}}[\mathbb E\{Y_t(a)-Y_t(b)\mid H_t\}]\)
is identified over histories generated by the logger. For nonstationary streams, \(d_{\mathrm{log}}\) must specify the mixture over decision indices; serial dependence affects uncertainty but does not remove current-step randomization. This applies to immediate block utility; if the estimand includes later outcomes, the continuation after each candidate action must be specified and held fixed. The six features need not be Markov for this history-averaged one-block estimand, though estimating conditional contrasts from them still requires adequate data and a stable model. Randomization identifies the population contrast; it does not validate the fitted model’s contrast, action ranking, or transport to histories generated by a different policy. Limited streams, nonstationarity, and model misspecification constrain precision and transport.

## Candidate model and what would be borrowed

Let \(x_t\in\mathbb R^6\) be the existing feature vector, which already includes its bias term and five covariates. Let \(\phi_a\in\mathbb R^3\) be fixed four-arm contrast codes satisfying \(\sum_{a=1}^4\phi_a=0\), with the 4-by-3 code matrix full rank. A linear candidate is

\[
\hat q(x,a)=x^\top\hat\beta+
(\phi_a\otimes x)^\top\hat\gamma ,
\]

where \(\hat\beta\in\mathbb R^6\) is the shared mean under the uniform logging mixture and \(\hat\gamma=\operatorname{vec}(\hat\Gamma^\top)\) for \(\hat\Gamma\in\mathbb R^{3\times6}\), the three action contrasts. The implied four effects are centered: \(\sum_a \hat\tau_a(x)=0\). There are 6 baseline coefficients plus 3 × 6 contrast coefficients, 24 total—the same count as four separate 6-coefficient heads. If the same discounted least-squares objective is solved exactly at each prefix (or its recursive sufficient statistics are transformed exactly) and regularization is transformed equivalently, this is only an invertible reparameterization of those four heads and must give the same predictions. For example, with orthonormal contrast codes, the separate-head ridge penalty \(\lambda\sum_a\|\theta_a\|^2\) becomes \(\lambda(4\|\beta\|^2+\|\Gamma\|^2)\) in baseline/contrast coordinates. Applying an untransformed equal penalty to \(\beta\) and \(\Gamma\), residualizing outcomes against a separately estimated baseline, or changing baseline/contrast update coupling changes the estimator and may be substantive; none automatically improves prediction or action ranking. A future comparison would need a matched reparameterized-head control, then test any changed shrinkage, residualization, or update rule against it.

The conceptual borrowing is from the R-learner: estimate a conditional outcome baseline \(m(x)\), then learn treatment effects from the part of the observed outcome left after removing that baseline. For a binary treatment, Nie and Wager write the residual relation as \(Y-m(X)=(W-e(X))\tau(X)+\epsilon\) and fit a residualized loss; in this setting the direct four-arm analogue uses centered action contrasts and known \(e_a=0.25\). [Nie and Wager, *Quasi-Oracle Estimation of Heterogeneous Treatment Effects* (2017 preprint)](https://arxiv.org/abs/1712.04912).

A narrow online adaptation would use only the actually selected \(A_t\) and its observed target \(Y_t\): predict \(\hat q(x_t,A_t)\) before seeing the block outcome, score that prediction, then update the shared baseline and contrast model using this one observed pair. To match the existing four-head ridge with \(\lambda=1\) and discount \(0.97\), a joint implementation would need the transformed regularizer described above, plus the same predict-before-update timing and discounted objective. Applying \(\lambda=1\) uniformly to the baseline and contrast coefficients would instead change the estimator. The discount and finite-memory online update are engineering choices; they are not supplied or justified by the R-learner paper. A discounted recursive implementation would also need to specify whether the baseline and contrast terms are fit jointly or through a separately cross-fitted baseline. Reusing the same small stream to fit a baseline and immediately residualize against it does not automatically inherit the paper's orthogonality or cross-fitting guarantees.

This would borrow an estimation template, not its theorem. The R-learner analysis is for independent examples with potential outcomes and unconfounded treatment conditional on observed \(X\); its cross-fitting and rate assumptions do not directly cover 64-step, nonstationary streams where prior actions affect later training data and histories. The six features may not be a sufficient state for long-run prediction. The randomized logger can identify a population one-step contrast as described above, but the fitted interaction is only an exploratory prediction unless its specified contrast and design-based uncertainty are actually evaluated.

## Optional one-step doubly robust score

For a policy \(\pi\) fixed before evaluating a held-out stream, a contextual-bandit doubly robust contribution at logged history \(x_t\) is

\[
\hat q_\pi(x_t)+
\frac{\pi(A_t\mid x_t)}{0.25}
\{Y_t-\hat q(x_t,A_t)\},
\qquad
\hat q_\pi(x)=\sum_a\pi(a\mid x)\hat q(x,a).
\]

For a deterministic target action \(a^\star\), this is
\(\hat q(x_t,a^\star)+4\,\mathbf 1(A_t=a^\star)
\{Y_t-\hat q(x_t,A_t)\}\).
Use a pre-outcome prediction and, for an empirical evaluation, fit the nuisance predictor without the evaluated seed (or another defensible held-out split). This is a correction to a *policy-value estimate at logged histories*, not a label for an unchosen action. No per-decision counterfactual outcomes are observed or should be imputed.

Dudík, Langford, and Li's original contextual-bandit paper explicitly treats chosen-action-only feedback, defines this baseline-plus-propensity-weighted-residual estimator, and proves a double-robust property for policy value under its contextual-bandit data model. [Dudík, Langford, and Li, *Doubly Robust Policy Evaluation and Learning* (ICML 2011; arXiv)](https://arxiv.org/abs/1103.4601). With the known logger here, propensity estimation is unnecessary; a deterministic target action still has importance weight 4 when selected and 0 otherwise. At 64 uniformly randomized decisions, the expected number matching one fixed target action is 16 per stream, not a promise of a particular realized count.

The scope matters. With the known randomization, this score can estimate the one-step value of a policy fixed before evaluation, averaged over histories generated by the logger, even when those histories depend on earlier logged actions. It does not by itself estimate the 64-step value of repeatedly choosing that policy. A target action changes subsequent model/data state, which changes later histories and outcomes. The behavior-history distribution is then not the target-policy trajectory distribution. Sequential policy evaluation needs an explicit transition / state model or sequential correction with support and variance analysis; multiplying importance ratios across a 64-step horizon can be unstable.

Kallus and Zhou obtain sequential results from a *specific* stateful contextual structure: exogenous arrivals and individual-level response not causally affected by the system state. Their analysis shows how one-step doubly robust information can support a marginal MDP in that special setting, and also that response-model error can persist over time. The present repeated-write setup has action-dependent future learner state, so that reduction cannot be presumed. [Kallus and Zhou, *Stateful Offline Contextual Policy Evaluation and Learning* (AISTATS 2022)](https://proceedings.mlr.press/v151/kallus22a.html).

## Memory and interpretation

Per scalar target, the 24-dimensional joint linear model has a dense float64 ridge Gram matrix, response vector, and coefficient vector use 4,992 bytes (24² + 24 + 24 numbers). Storing the symmetric Gram matrix packed uses 2,784 bytes (24×25/2 + 24 + 24 numbers), before small counters/configuration and runtime-object overhead. Discounting changes the sufficient-statistic values, not their dimensions. One can keep the DR estimate as a running aggregate for a pre-specified policy; a full event log is not required for that aggregate. These figures are parameter-state costs only and do not include the application or interpreter.

Lower utility prediction MSE need not mean better action ranking. Utility is a difference of targets: if \(e_U=e_R-e_C\), then
\[
\operatorname{MSE}(e_U)=\operatorname{MSE}(e_R)+
\operatorname{MSE}(e_C)-2\,\operatorname{mean}(e_Re_C).
\]
A better shared prediction of common reward/CPU difficulty can lower utility MSE while leaving pairwise action contrasts unchanged. Conversely, noisy common-level prediction can obscure useful contrast estimates. Ranking requires evidence about errors in \(q(x,a)-q(x,b)\), especially near ties; aggregate observed-outcome MSE does not provide that evidence. The observational calibration comparison is descriptive and cannot establish action ranking, causal benefit, or whole-policy value.

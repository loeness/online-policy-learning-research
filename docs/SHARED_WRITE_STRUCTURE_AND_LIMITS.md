# 当前共享写入机制：结构、决策与限制

## 策略参数

沿用共同预训练W0和固定源输出坐标。actor输入四个位置/目标坐标，产生64维特征h。令φ=[h;1]，H是4×3动作对比基，P=Hᵀ[W0_action|b0]是冻结的3×65矩阵。

情境被路由至局部槽j，当前x区域为b，所属共享组为g(j)。策略logit为：

`logit = logit_0 + H [A[j,b] + C[g(j)]] P φ`

每个局部槽A有三个3×3矩阵，共27个系数；每组C有一个3×3矩阵，共9个系数。不属于共享组时只使用A；无路由时只使用基础策略。六个局部槽全部计费。共享组最多两个，未使用的参数同样计费。

这是固定深度的加法共享结构，可用“基础→组→局部”的树描述，也可用分组模块实现。没有学习树拓扑、合并父子或自动提炼共同参数。新机制与旧V2的区别在于：**C是真正被在线奖励梯度持续更新的参数，而不只是保存时的编码中心**。

## 在线更新

PPO使用新采集的256步rollout；每1,024步中三个rollout用于训练，一个保留。基础actor及P固定，当前槽A、当前共享组C和公共critic可学习。其他局部槽不应被当前经验改写。critic输入四坐标加八个零，不包含route ID。

S1a/S1b采用float32持久编码，持续保留Adam状态。S2每1,024步实施真实INT8编码、解码和安装，并清除actor Adam状态；critic Adam保留。不能把两类cohort混合解释为一个容量或收敛结果。

## 目前实现的组织决策

| 决策 | S1b | S2 |
|---|---|---|
| 局部情境编号与切换 | 给定 | 给定 |
| 共享分组 | 512步实际动作探测，自举最多两组 | 给定家族，用于隔离容量效应 |
| 局部参数写入 | 当前情境对应的槽 | 当前缓存槽 |
| 共享写入 | 动力学组对应的C持续获得PPO梯度 | 家族C持续获得PPO梯度 |
| 淘汰/替换 | 六情境六槽，不耗尽 | 十二情境六槽，固定LRU |
| 淘汰后保留 | 不适用 | 保留C；清除被替换A及其优化器状态 |
| 策略收益可靠性 | 未单独估计 | 未单独估计 |

S1b的profile包含x区域、动作及实际位移的计数，保存支持度；它是有限历史摘要，不能代替一般POMDP的充分统计量。它忽略奖励，不具备识别任意控制目标的能力。回退到局部独立学习可以处理未分组，不等于已经实现未知路由下的探索。

## 容量口径

- S1：actor实际独立666 B、共享738 B，共同上限1,024 B。
- S2：actor实际独立204 B、共享230 B，共同上限230 B；仅限当前27系数/槽的编码，无法再放下第七个完整槽。
- 每次保存的W0文件＋一个智能体checkpoint≤256 KiB，含参数、critic、优化器、相应路由/分组状态和RNG。
- 研究日志、外生日程、历史checkpoint和源码快照不供部署智能体查询；运行期RSS单独报告。
- 周期保存不含环境与部分episode状态，不能精确续跑中断的交互轨迹。详见[S2复核](SHARED_WRITE_CAPACITY_REVIEW.md)。

共同上限不等于实际字节相同。共享方法实际多占72 B（S1）或26 B（S2），不得直接宣称整体压缩获胜。

## 尚待建立的核心算法贡献

当前机制能够检验在线共享参数是否带来跨情境迁移，以及局部参数被淘汰后是否仍有复用效果。它尚未完成“在线经验自动决定知识形成、共享写入与替换”的完整方法：

1. 在未知任务边界下，将有限历史可靠路由到可更新的参数，避免旧样本写入新槽或新组。
2. 独立判断动力学/情境匹配和共享参数的策略收益，处理奖励冲突及不支持的动作。
3. 根据实际跨情境帮助而形成、拆分或更新共享组，而非固定最多两组的相似性启发式。
4. 在完整持久预算下学习保留与替换，超过固定LRU；验证共享、专化和压缩之间的选择。
5. 用多W0、不同任务结构和标准基准检验成本与性能权衡。

因此，后续研究的重点仍是组织与存储决策规则；上述加法容器和确定性动作映射实验是机制基础。

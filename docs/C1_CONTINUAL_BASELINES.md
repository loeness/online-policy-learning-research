# C1 full fine tuning and replay controls

This note specifies the online controls added alongside the frozen-actor C1 residual study. They use the same source `TreePolicy` checkpoint, 13-value C1 observation, four-action distribution, simulated reward, route input convention, and PPO rollout schedule. Their results must remain separate from the archived C1 formal cohort.

## Full fine tuning

`C1FullFineTunePolicy` copies the source feature extractor, actor, action head, critic, and value head. All copied actor and critic weights are trainable. The policy starts with the exact source weights (`W0`); the actor logits therefore match the foundation at initialization.

The route-conditioned control has one shared actor and one learned 6 × 64 route bias. At routes 1 through 6, the corresponding 64-value bias is added to the first hidden-layer preactivation. This is equivalent to appending six one-hot route inputs to the original first linear layer and initializing their columns to zero. The source actor weights and logits therefore remain exact at initialization, while each route can learn an unrestricted hidden bias. Route 0 applies no shift. Parent route 7 or 8 uses the mean bias among currently known endpoints in that family. The initial known endpoints are 1, 2, 4, and 5; `initialize_heldout(3)` or `initialize_heldout(6)` copies the mean bias of that endpoint's two seen siblings and marks it known. No independent actor, action head, or critic is stored per endpoint.

Before Step 3, an additional zero-initialized 3 x 64 visible-band bias was added at the same hidden preactivation to give full fine tuning the band prior supplied to compressed controls. This amendment is specified in `docs/C1_SUPPLEMENT_AMENDMENTS.md`; it is included in weights, Adam moments, Fisher and reference state. The full reference exceeds both original adaptive caps and uses a separately declared 393,216-byte complete-state cap. This is an outside-budget reference.

The matched `route_conditioned=False` control is also available. Its actor receives only the four navigation coordinates and ignores the route field, so it cannot hold simultaneous route-specific behavior in its shared weights. Report it as a context-stateless full fine-tuning control, not as the only full-capacity comparison.

Both variants keep the critic input path from the source policy: the four coordinates and eight history-summary values. Route IDs are actor-side controls, not simulator observations. In oracle-route phases, this is an explicit upper-control with route identity supplied. If a run uses estimated routes, record that mode and the route source.

The policy supports Adam and SGD. Adam is the reference full fine-tuning optimizer; SGD is a state-size option and must be identified in results. Record the trainable actor parameter bytes, actor optimizer-state bytes, full policy tensor bytes, full optimizer-state bytes, rollout storage, router, and serialized agent together. Include the replay arrays when using the replay control. Classify full fine tuning as outside the original adaptive budget. Apply its predeclared 393,216-byte complete-state cap; exceeding that cap is a run failure. Do not shrink the source network, drop its weights, or silently change the optimizer to make it fit. The `adaptive_actor_tensor_bytes` field counts the shared actor and route embedding with their optimizer state and excludes the critic.

Because actor weights are intentionally trainable, use `parameter_update_scope` (`full_actor_critic` or `full_actor_critic_plain`) in run records. A frozen-base actor hash assertion is not an appropriate validity check for these controls. Track the initial parameter hash and report actor and critic updates explicitly.

## Online elastic weight consolidation

`C1OnlineEWC` applies a diagonal Fisher-weighted quadratic penalty to the shared actor and route embedding. The Fisher is the mean of per-transition squared score gradients, `mean_i[(d log pi(a_i | s_i) / d theta)^2]`; it does not square a gradient averaged across a batch. At each fixed 2,048 online-step checkpoint, `C1ContinualPPO` samples up to 64 observations and the actions actually taken from the most recent PPO rollout, estimates the per-sample Fisher at the updated policy after the PPO/replay update, and consolidates it at the same reference. The schedule follows total environment interactions and does not inspect episode boundaries or task labels. Fisher computation uses existing rollout data and adds no environment interactions.

For a source-aware prior, call `initialize_source_ewc(source_observations, source_actions=None, sample_size=64, seed=...)` after installing the shared core and before online learning. This anchors the penalty at the exact source actor (`W0`) and estimates a source Fisher from previously collected source observations. Four-coordinate source data is augmented with zero history and root route 0 to match the C1 source input. If source actions are omitted, the frozen source policy samples them from its own action distribution. Record the source observations and any offline data preparation separately from C1 deployment interactions. Without a source prior, online EWC begins consolidating after its first fixed checkpoint.

EWC contributes its gradient to each actor update in the ordinary PPO minibatch epochs and the optional replay update. After those updates, the new Fisher is consolidated into the online importance and the actor reference moves to its current parameters. The saved sample comes from the latest real rollout. Fisher and its new reference are evaluated after PPO and replay, at the same parameter values; this is an empirical Fisher under collected actions rather than an exact expectation under the updated policy. The PPO update counts remain the ordinary PPO epochs, with any replay update reported separately. Tune and report the EWC coefficient (this protocol tries 10, 100, and 1,000) on validation data before formal runs. `C1OnlineEWC.storage_report()` separates the Fisher tensor bytes from the reference actor bytes; count both in full agent storage. Its `state_dict()` preserves the anchors, Fisher, decay, and consolidation counters.

## Bounded policy replay control

`C1ContinualPPO` performs the normal PPO epochs, then takes one additional optimizer step on a uniform sample from a fixed-size online reservoir. Each retained item is a 13-value policy input and the four action probabilities produced by the policy when that state generated an action. The loss is `KL(teacher || current policy)` multiplied by a configured coefficient. No task label, reward, transition, or network snapshot is stored. With the default capacity of 256, the two float32 arrays use 17,408 bytes (68 bytes per item), independent of stream length. Set `replay_capacity=128` for the 128-item replay variant. Replay-only mode supports any adapter core with `get_distribution` and `evaluate_actions`, including frozen-base C1 residual policies; set `ewc_coefficient=0` for those policies. EWC is restricted to the full fine-tuning actor.

The caller records `observe_online(pre_action_observation)` as the behavior policy produces each action, before the next PPO update. The reservoir uses Algorithm R, so every observed item has equal long-run inclusion probability. It samples uniformly for the replay update. The policy distribution stored as teacher is the actual epsilon-mixed, temperature-scaled action distribution used by the control.

This is a bounded behavior-cloning replay baseline inspired by the policy consolidation and replay ideas in [CLEAR (Rolnick et al., 2019)](https://arxiv.org/abs/1811.11682). It is not a faithful CLEAR implementation: it does not use IMPALA/V-trace, off-policy PPO replay, value-function distillation, reward replay, or CLEAR's complete training setup. Report the exact replay capacity, coefficient, batch size, optimizer, bytes, and number of extra replay steps. Keep this baseline's interaction stream and selected hyperparameters separate from the frozen C1 runs.

## Checkpoint and accounting interface

The policy exposes `to_spec`, `from_spec`, `optimizer_manifest`, `export_payload`, and `from_payload` for restorable checkpoints with optimizer state named by policy parameter. `storage_report(optimizer)` reports actor, route embedding, critic, and optimizer tensors separately. `C1BoundedBehaviorReservoir.storage_report()` reports allocated array bytes and retained count; `state_dict()` and `load_state_dict()` preserve its arrays, counters, and sampler RNG. `C1ContinualPPO.continual_state_dict()` preserves the replay and EWC state, schedule, and RNG. Pass replay and EWC state as `replay_state=` and `ewc_state=` to `export_payload` when checkpointing continual learning. Include other runner state, such as the router and rollout buffer, in the same measured bundle as C1.

Do not merge full fine tuning or replay results into the existing C1 tree, flat, or dictionary tables. The original C1 question and archive remain unchanged; these controls add the missing full-update and public replay comparisons needed for the next online tuning study.

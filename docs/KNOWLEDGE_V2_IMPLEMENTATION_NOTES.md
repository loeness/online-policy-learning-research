# V2 实现复核补充

2026-10-15，正式训练运行期间的独立复核。

V2 保存的 EvidenceRouter 状态不能由 V1 默认工厂直接加载，因为构造参数与旧路由不同。新增 `scripts/restore_knowledge_v2.py` 从每个结果的 `runtime_patches.json` 读取 condition，并在同一算法工厂下加载原 checkpoint。训练及保存内容不变，三个新路由 pilot 的完整路由状态、计数和修正矩阵已经逐一还原验证。后续评估必须使用该工厂，不能调用 V1 默认路由加载器。

V2 规程提出的 behavior-relative surrogate 辅助诊断函数已实现并有数值测试，但初始训练 harness 没有将它写入逐次整合日志。不得声称该指标已在主正式 cohort 中观测或校准。主比较仅依赖实际在线回报、路由、字节和候选 KL；非阻塞整合不使用该分数接受/拒绝局部学习。若单独补做分数诊断，输出和交互另计，仍返回原分数以保持被诊断算法的行为。

随后单独运行 `diagnose_knowledge_gate_score.py`：seed787、8,192步，在原门控调用位置同时计算旧分数与以实际行为概率为分母的分数，始终返回旧分数。与原新路由门控pilot的8,192个action/reward逐项完全一致。共10次候选/回退probe有4次符号不同；这说明两个经验评分会给出不同判断，不证明任何一个评分具有真实值函数的安全保证。该开发诊断不并入正式三种子的效果统计。

容量报告还应读取所有 `capacity.csv` 采样，而非只看整合后的编码。新槽分配会触发继承的重编码路径；即使一次共享候选比int8更小，区间内的编码大小也不必与该次提交值相同。恢复包上限和修正320 B边界仍单独检查。

“恢复包”计量指 W0 文件和持久化 checkpoint；静态算法代码和必要 condition 工厂通过源码快照及 runtime_patches 记录。它不是任意环境/rollout 时刻的断点续训格式，也不等同于全部运行时内存上界。

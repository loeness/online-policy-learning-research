# 重访评估修正：训练流保持原样

2026-10-15，在在线正式实验运行期间的根代理代码复核发现两项仅影响终点重访解释的问题。

1. 原重访程序让路由原型继续更新，却没有在原型槽被重新分配时清除该槽原有策略修正。新情境因此可能调用被驱逐旧情境的修正。训练程序有 allocation/generation 处理，不受此问题影响。
2. 原重访为每个情境使用相同 action RNG 初始种子，但连续跨 episode 消耗 RNG。两种条件若 episode 长度不同，后续 episode 的动作随机数就不再按 episode 配对。

修正要求：保留全部原训练和旧重访结果，旧重访标为不适于持久参数效果的正式结论。从最终 checkpoint 重新加载两份同样的策略/路由初始状态，清空短历史。路由 observe 报告新分配时，仅对非共享单头方法清除对应旧修正行，不进行梯度更新；记录结构清除次数。single_head_online 的全局修正不属于路由槽，不因路由分配清除。每个情境×episode 使用相同 reset seed 与独立、相同 action RNG seed，从而动作随机流不会跨 episode 错位。

所有六个含策略修正的实验臂、三个种子、六情境各八个完整 episode、保留与清除两条件均重做。无修正的 adaptive_assignment 臂不适用此消融。输出到 `outputs/knowledge_loop_revisit_corrected`，另计仿真交互、CPU/墙钟，保存修正程序与依赖快照。原始 `outputs/knowledge_loop_formal` 不覆盖。汇总报告只使用修正版重访推断参数持久性，在线累计奖励仍使用原正式训练流。

这项修正不选择新的学习超参数，不改变已得到的训练策略；其代价是增加一轮单独计量的评估。原旧重访消耗仍进入总成本账本。

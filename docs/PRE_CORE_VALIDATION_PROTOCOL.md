# 核心机制验证前：定义、猜想与前置诊断

日期：2026-10-15。原 A/B/C1 及其强对照已经完成。本文回应“进入 C1 前应明确什么”，将其解释为进入新的自动知识组织核心机制实验前的准备；不重跑原 C1，不启动完整 C2/C3。树、DAG 和模块池均为可检验的结构假设。

## 1. 必须先明确的定义

1. **研究对象**：预训练提供初始策略，在线奖励产生跨部署保留的策略知识；组织与存储决策服务于长期控制表现。短历史适应、统计模型更新与神经参数学习都应诚实区分，不预设某种实现必胜。
2. **因果时序**：行动前只能使用过去事件和当前观测。写作 `z_t=f(h_{t-1},s_t)`、`a_t~pi(s_t,z_t;M_t)`，获得 `e_t=(s_t,a_t,r_t,s_{t+1})` 后才更新 `M_{t+1}=U(M_t,e_t)`。不能用包含下一状态的事件为同一步动作路由。
3. **环境范围**：第一版研究可复现、具有可压缩共享关系的未知情境流；情境编号、边界、生成因素仅供评估者使用。辨识依赖可访问证据与必要探索；若两个情境在已执行动作下完全不可区分，不能要求即时正确识别。需覆盖缓慢漂移、控制需求冲突和稀有复现。
4. **主要判据**：固定容量下的实际在线累计回报/每步回报，配合重访恢复交互数、旧情境损失、适应速度和整合计算。最终成功率不是唯一目标。未知最优策略时，不把回报差冒充严格 regret。第一阶段验证可压缩性与可辨识性，不承诺有限记忆对任意无限新任务均不遗忘。
5. **容量口径**：分别记录持久策略知识、路由/统计、可恢复的 optimizer/replay、临时 rollout/候选工作区、实际序列化与进程峰值。模型规模和完整可恢复学习状态不是同一指标；报告中同时给出。不能通过未计费副本、旧日志或无限试用槽恢复被删除知识。
6. **候选知识单位**：先用现有紧凑修正和统一坐标验证写入规则；不能根据可任意重参数化的参数距离直接认定知识相同。不同结构共享相同模块、优化器、路由与预算，隔离组织规则的效果。
7. **主算法焦点**：先局部学习，再依据跨情境改进证据决定共享/整合；合并、拆分、替换从同一损失与预算判断派生。第一版不同时实现所有结构操作。

## 2. 已有证据与缺口

已有：固定家族下紧凑在线修正可学习；共享先验可改善部分复用。树与相同加法分解的扁平表示可完全等价。固定源输出基的优势不等于自动整合的压缩优势。

缺口：无标签从零情境发现；可靠的局部/共享写入；真实释放容量的整合；满容量替换；独立的策略改进可靠性；多个独立预训练 W0；超出动作置换先验的环境。现有解析在线控制器很强，不能声称当前导航证明持久神经更新不可替代。

## 3. 可证伪的猜想与顺序

| 编号 | 猜想 | 最小实验与对照 | 失败后的修改 |
| --- | --- | --- | --- |
| H1 | 在线局部修正存在可复用但非普遍兼容的部分 | 同一 W0、统一修正坐标，单情境更新后交叉评估其他情境；记录有向迁移矩阵，与家族和梯度/更新相似性比较 | 若无可共享信号，检查更新是否已学会，再更换环境/知识单位；不直接构建更深树 |
| H2 | 廉价在线信号能够预测共享的收益与损害 | 在线训练数据提出候选，独立后续流检验；比较梯度相似、预测相似、决策证据，记录误接受与误拒绝、证据成本 | 若失准，缩小共享步长/影响范围，局部保留；不能把 ensemble 方差当严格置信界 |
| H3 | 整合产生真实容量收益或更优同预算回报 | 相同源基、精度、optimizer，比较独立模块、共享+压缩残差、周期蒸馏；在整合前后量字节与策略损失 | 若只增加父参数而未释放容量，不称压缩；改残差编码或改为研究同预算泛化 |
| H4 | 无标签历史可支持必要的控制情境辨识 | 不用预校准 bank，随机非回合边界切换；加入未尝试动作和主动探测；共用路由器隔离组织规则 | 若不可辨识，增加有预算探测或缩小识别目标；不能靠任务标签修补主方法 |
| H5 | 满容量时，整合/替换比简单保留规则更划算 | 情境数超过容量，含稀有难重学情境；对比 FIFO/LRU/LFU、随机、周期蒸馏和无整合 | 若收益被维护成本抵消，降低整合频率/算子复杂度；缩小优势声明 |
| H6 | 结构应随共享关系改变 | 嵌套、交叉、相似观测但冲突控制三类流；固定写入规则，对比树与稀疏模块池 | 若无差异，选简单结构；不把树形容器当贡献 |
| H7 | 持久参数知识提高重访效率，且不依赖单个 W0 | 清空短历史、保留/清除修正/路由状态的配对重访；与强有界历史统计/循环基线比较；至少多个独立预训练 W0 | 若历史基线同样好，承认其在线学习作用，检查任务是否体现持久整合价值 |

H1 与 H3 的可行性是开展自动整合前最直接的两个门槛；H2/H4 可先在受控范围内逐步推进。H5/H6/H7 是形成最终贡献所需证据，不应全部当成开始写第一版算法前必须完成的成果。

## 4. 本轮 P0 诊断规程（正式运行前固定）

目的只验证 H1 并初探 H2：当前 C1 的家族标签是否对应可迁移的修正；廉价相似性是否足以决定共享。不是 task-free 算法，不是动态结构实验，不是容量压缩对照。

- 输出根：`outputs/pre_core_p0`，独立于既有所有结果。
- 同一个已有 `data/foundation.pt`；部署种子 271、283、307。没有超参数搜索。
- 六个情境各自从相同 W0/零修正/新 optimizer 开始，以 `output_mixer` 的冻结源基和唯一 active route=1 学习 4,096 实际 PPO 步。训练动作不接收情境或家族编号；外部实验者隔离情境并在各独立运行之间重置智能体，这不构成无边界持续学习。其余预分配槽保持零，仍如实记录；该设计不宣称容量最优。
- PPO 沿用既有实现：rollout 256、batch 64、epochs 4、gamma 0.98、GAE 0.95、clip 0.2、target-KL 0.06、学习率 0.003、entropy 0.06、temperature 2、epsilon 0.05。只使用真实仿真交互奖励，不使用专家更新目标或隐藏动作映射。
- 保存首次 rollout 的 actor surrogate-loss 梯度（统一 27 维局部修正坐标），以及最终修正向量；梯度信号受 critic、访问分布和采样噪声影响。比较的是该廉价信号对有限 PPO 更新后迁移的预测，不能解释为梯度在无穷小步长下一阶结论的反例。
- 将每个学到的候选原样用于全部六个目标；所有目标仍固定 route=1，不使用目标标签切换候选。每次评估 32 个完整 episode，max 64 步，基线与候选使用同一 episode reset seed 和同一按步 action-uniform 流。比较配对 episode 回报差为主，成功率与长度为辅。
- 每个部署种子只需评估一次各目标零修正基线。主迁移矩阵 `T[i,j] = mean_episode_return(candidate_i,target_j) - mean_episode_return(W0,target_j)`，有向且不强制对称。家族标签只在完成后汇总同/异家族差异。
- 相似性事先固定为同坐标展平 27 维向量的 cosine：首次 rollout 梯度 cosine 与最终修正 cosine。分别按 seed，在 30 个非对角迁移单元中，报告 cosine 与 `T[i,j]` 的 Pearson 描述性相关、正 cosine 对应负观测迁移的数量，以及同/异家族平均迁移。零范数的 cosine 记为未定义而非填成匹配。不给这些依赖单元计算独立样本显著性或置信保证，不以结果选择阈值。这是有限 PPO 更新下的预测关联诊断，不是相似性的因果实验。
- 记录每个 episode 的实际步数/回报、训练步骤/optimizer 步数、CPU/墙钟、RSS 采样、模块/optimizer 字节、基础 actor hash、初始梯度和最终参数。所有离线交叉评估交互单独计量，不能当作部署算法可免费获得的反事实。
- 训练固定 73,728 步；评估为 3×6 个基线批次加 3×6×6 个候选批次，共 126 批，每批 32 episodes，共 4,032 episodes，最多 258,048 步。总仿真上限 331,776 步，不含软件 smoke check；实际以账本为准。
- 4,032 个策略评估 episode 共享 576 组独特的配对 reset/action 随机流（每个 seed×target×episode 一组），不是 4,032 个相互独立的随机场景。
- 不挑最好 seed、不据测试回报重新调参。3 个部署种子与一个 W0 仅属机制探索；不以 90 个 off-diagonal 单元当作 90 个独立样本做显著性检验。
- CPU 单进程、torch threads=1；本机为 i9-13980HX / RTX 4060 Laptop 8GB / 16GB RAM，现有 torch 是 CPU build。优先复用环境，避免在低可用内存时并发重任务。

### 预声明的解读边界

1. 先看 self-transfer 是否大多为正；若训练本身未学到，跨情境失败不能否定共享假设。
2. 再看正/负迁移是否并存，及同家族是否整体更有利。这验证共享关系的任务相关性，不证明可在线自动发现。
3. 初始梯度相似、最终参数相似与实际迁移不一致时，只能否定“该信号在本诊断中可直接替代验证”的强假设。
4. 该环境的共享源基和动作置换先验仍然有利。即使 P0 成功，也必须补超出该先验的控制任务与多个独立 W0。

## 5. 最小推进顺序

1. **现在**：完成 P0，确认局部学习与跨情境迁移信号；据此选择“候选提出”和“候选接受”是否需要不同证据。P0 没有自动组织机制，不能据此宣告核心贡献成立。
2. **随后两个隔离实验**：一是同表示、同字节预算下的静态整合，检验 H3；二是从零无标签的历史辨识与主动探测，检验 H4。先分开，是为了避免路由错误和整合错误相互遮蔽。
3. **再实现最小闭环**：只保留局部试用、共享候选和一次容量替换；固定容量、未知边界，在真实单条交互流中决定，不使用评估者的迁移矩阵。算法不能免费回到任意旧环境评估候选。
4. **论文贡献验证**：加入交叉因素、欺骗性相似、容量饱和与稀有重访；比较简单固定/扁平结构、周期蒸馏与梯度驱动结构。多个独立 W0；统一模块和调参预算；完整成本曲线。

整合若必须大量额外交互才能筛选，其成本可能超过节省的再次学习交互。这一“证据获取是否划算”应作为核心闭环实验的一部分，而不是在论文最后只列算法时间复杂度。
